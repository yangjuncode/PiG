PiG 代码精读 · 第 1 课

架构地图：一次 prompt 的旅程

你的目标是写自己的 agent。这一课先回答一个问题：PiG 几十个子系统里，哪些是"任何 coding agent 都需要的骨架"，哪些只是"这个产品特有的表面"——以及你敲下回车后，代码到底沿着什么路径跑。

1先建立取舍的镜头

PiG 是移植项目，不是从零设计的 agent。这意味着代码里混着两种东西：

层对你的价值包
骨架：agent 引擎 + 模型抽象 直接借鉴——这是每个 coding agent 的心脏 agent/、ai/
外壳：把引擎包成产品 参考——会话管理、设置、CLI 模式、渲染 internal/codingagent、cmd/pig、tui/、durable/
生态：扩展、包、Piglet 可选——看你自己的 agent 要不要插件机制 coding/extension/、extensions/sdk*、coding/piglet*
移植地基：TS/Node 语义复刻 跳过——只有"移植"这个任务才需要它们 internal/nodepath、internal/jsstring、internal/jsonparse…
核心洞察 internal/ 下一大半包不是"Go 工具库"，而是 Node.js 运行时语义在 Go 里的复刻——nodepath 复刻 path.win32/posix，jsstring 复刻 UTF-16 字符串行为，jsonparse/jsonstringify 复刻 JS 的 JSON 边界行为。写自己的 agent 时你完全不需要这一层；它存在的唯一理由是 parity（行为必须和 TS 上游逐字节一致）。

2架构地图：包即上游镜像

PiG 的顶层包刻意与上游 Pi 的 npm 包一一对应（docs/pig-architecture.md）：

cmd/pig ── 入口：flags、app mode 分发、子命令
   │        （交互 / --print / --mode rpc / pig package / pig piglet …）
   ▼
internal/codingagent ── 产品壳（924 个文件，最大的一块）
   │        Session 生命周期、settings、交互模式编排、事件桥接
   ▼
┌─ agent/ ──────────── agent 引擎：Agent 类型 + runLoop + 工具执行
│    mirrors packages/agent
│    NewAgent(opts) → a.Send(ctx, text) → 事件流 → []AgentMessage
│
├─ ai/ ─────────────── 模型抽象：Provider 接口、Model、SSE 流、各 provider
│    mirrors packages/ai       （anthropic.go / openai / google / bedrock …）
│
├─ tui/ ────────────── 终端 UI：编辑器、viewport、渲染器
│    mirrors packages/tui
│
└─ durable/ ────────── 会话/任务/文档的持久化类型
     mirrors packages/durable

生态层（你自己的 agent 可以之后再决定要不要）：

coding/extension/host/ ── 扩展宿主：子进程 wire 协议（protocol.go 是权威）
extensions/sdk{,-rs,-py,-ts} ── 同一 wire 契约的四种语言 SDK
coding/piglet{,build}/ ── 把"agent + 扩展 + 提示词"打包成可分发单元
coding/mcpext/、mcp/ ── MCP（Model Context Protocol）接入
test/parity/ + .upstream/current/ ── 移植专用的校验体系
旁注：为什么 internal/codingagent 有 900+ 文件？因为它对应上游的 packages/coding-agent——一个完整产品：会话文件、斜杠命令、设置、认证、工具实现、交互编排全在里面。"引擎小、外壳大"是这类产品的常态。

3一次 prompt 的旅程

你在 TUI 里敲下 帮我修一下这个 bug 然后回车。以下每一步都可以在代码里定位（给了文件名和函数名）：

  1. 入口分发 cmd/pig/main.go

    main() 解析 flags，processAppMode(flags) 判定为交互模式，构造 codingagent.NewInteractiveMode(iopts) 并运行。启动期工作（settings、扩展加载、模型解析）都在这一步完成。

  2. 输入捕获 tui/ → internal/codingagent/interactive_*.go

    TUI 的编辑器组件拿到回车事件，InteractiveMode 把它变成一次 prompt，交给持有 agent.Agent 的会话。

  3. 进入主循环 agent/agent.go:1005 → agent/agent_loop.go

    a.Send(ctx, content) 把用户消息追加进 transcript，然后 runAgentLoopContinue → runLoop → r.loop() 开始按 turn 迭代。这个文件（548 行）是整个 agent 的心脏。

  4. 组装请求 agent/agent_loop.go

    每个 turn：prepareRequest 计算系统提示与上下文，transformContext 钩子允许扩展改写消息列表，然后 streamAssistantResponse → requestStream → streamWithProvider。

  5. 调模型 ai/（如 ai/anthropic*.go）

    provider 把标准化 transcript 转成自己的 wire 格式，发 HTTP/SSE 请求，产出统一的 AssistantMessageEventStream。ai/types.go:687 的 Provider 接口就是"换模型"的接缝。

  6. 流式广播 agent/lifecycle.go → internal/codingagent/interactive_events.go

    流事件逐步拼出 AssistantMessage；a.Subscribe(listener) 注册的监听者收到 MessageStartEvent / MessageUpdateEvent / …。handleAgentEvent 把事件一路桥接给 TUI 渲染和扩展宿主——这是"引擎不依赖 UI"的关键：UI 只是订阅者。

  7. 工具回合 agent/run_tool_call.go

    若 stopReason == "toolUse"：按 ToolExecutionMode 并发执行工具调用，结果包成 ToolResultMessage 追加进 transcript，loop 进入下一 turn——模型再次看到全部上下文。

  8. 收尾落盘 internal/codingagent + durable/

    直到 stopReason == "stop"：AgentEndEvent 广播，SessionManager 把新消息持久化到 session 存储。一轮结束，等下一次输入。

带走的模型 最小可用 agent 只需要三样：一个 transcript 循环（agent/）、一个 provider 接缝（ai.Provider）、一组工具（agent.AgentTool 接口）。UI、会话文件、扩展、包管理全是可插拔的外壳。你写自己的 agent 时，第一课要抄的就是这条边界。

4 retrieval practice：合上地图回答

Q1 · 一次 prompt 的正确旅程顺序是？

主循环（agent/agent_loop.go）在 provider 之上——它决定何时调模型、何时执行工具。provider 只负责"把 transcript 变成事件流"，不知道工具循环的存在。

Q2 · 你要给自己的 agent 接入一个新 LLM provider，最该精读哪两个接缝？

Provider 接口（ai/types.go:687）定义"怎么调模型"；StreamFn 是 agent loop 实际调用的函数形状（agent/stream_fn.go）。替换模型 = 实现这组接口，其他层不动。

Q3 · internal/nodepath、internal/jsstring 这类包存在的理由是？

这是"移植"任务特有的地基：TS 的 path、UTF-16 字符串、JSON 边界行为必须在 Go 里逐字节复现，parity 场景才过得去。从零写 agent 完全不需要它们。

Q4 · PiG 把第三方扩展跑在哪里？（提示：AGENTS.md 明确禁止了几种替代方案）

子进程隔离让扩展可以用任何语言写（Go/Rust/Python/TS 四套 SDK 共享 protocol.go 这一个 wire 契约），崩溃不拖垮宿主。这是产品决策，不是移植要求——你自己的 agent 可以选别的。

Q5 · 打开 agent/agent_loop.go 看一眼：runTurn 的返回签名是？

三个返回值各管一件事：本轮产出了什么、循环该不该继续、有没有出错。这是"一个 turn"与"整个 loop"之间的接缝——下一课精读 agent loop 时它就是入口。
