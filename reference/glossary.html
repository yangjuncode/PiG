PiG 术语表

这个项目的词汇分两套：一套来自"移植"纪律（parity、divergence、upstream pin），一套来自产品生态（Resource、Package、Piglet）。读代码时遇到黑话回这里查。权威出处永远是 docs/piglet-resource-ontology.md 和 AGENTS.md。

移植纪律词汇

Pi / upstream
上游 TypeScript 参考实现（github.com/earendil-works/pi），镜像在 .upstream/current/。行为唯一权威：PiG 与 Pi 不一致 = bug 或记录在案的 divergence。
PiG / pig
本项目：Pi 的 Go 移植，单原生二进制，不需要 Node.js。二进制名 pig，配置根 ~/.pig（$PIG_HOME）。
parity
"可观察行为与上游一致"。校验手段：test/parity/scenarios/ 里的 TOML 场景成对跑 Pi 和 PiG 比较输出。
divergence / D<n>
有意为之的行为差异，必须编号记录在 docs/parity/DIVERGENCES.md。静默漂移是这个项目最大的忌讳。
UpstreamVersion
当前对齐的上游版本，钉在 internal/coding/pigversion/pigversion.go，经 coding.UpstreamVersion 再导出。
PORT_MAP
docs/parity/PORT_MAP.md：上游每个文件 → Go 文件 / deferred / designed-out 的对照表。定点深入时的导航。
scenario / family
test/parity/scenarios/<family>/*.toml：一个可观察行为的成对断言。family 按上游功能域分组。
"Mirrors packages/…" 注释
Go 文件头的出处声明，指向对应上游源文件路径。看到它就知道了该去 .upstream/current/ 哪个文件对照。
Stock PiG / PiG Standard
Stock = 裸仓库版（只含上游行为 + 惰性通用机制）；PiG Standard = 一个显式 Piglet，承载品牌化/有主见的产品行为。Stock 绝不激活 Standard 行为。

生态本体词汇

Resource
最小能力单元：一个 extension、skill、prompt、theme、hook、MCP 定义、跨工具 agent 或 agent 环境。是被分发/被选择的东西，不是进程。
Package
资源的"分发信封"：把若干 Resource 分组发布/安装。只能装资源，不能装 Piglet。
Piglet
一个"命名的 agent 定义"：选定并组合一组 Resource/Package/Plugin，加上自己的作用域与环境要求。类比："PiG 是烤箱，Piglet 是菜谱"。
Piglet Binary
把一个 Piglet 连同所需组件构建成目标平台的独立可执行文件。组件实现方式（realization）可以是 fused / subprocess / external。
Piglet Image
同一 Piglet 组合的 OCI 镜像形态。
realization vs materialization
两条独立轴：realization 回答"组件用什么方式跑"（fused=编译进二进制 / subprocess=独立进程 / external=外部服务）；materialization 回答"以什么载体交付"（binary / release / agentEnv / external）。不要把它们混成一个概念。
runtime cell
扩展宿主侧的优化：把多个兼容扩展"打包"进一个子进程（packed cell）。对扩展必须观察上不可区分——每个扩展仍独占一个 socket、一次 register 握手。
wire protocol
扩展子进程与宿主间的通信协议，唯一权威：coding/extension/host/subprocess/protocol.go。四套 SDK 共享同一契约，无版本协商。
SDK（sdk / sdk-rs / sdk-py / sdk-ts）
同一扩展 API 的四语言实现。接口与行为必须一致，实现可自由。sdk-ts 只是声明层适配，运行时仍走 Node 子进程。

引擎内部词汇

Agent / agent loop
agent/ 包的核心：Agent 类型持有 transcript + 工具 + 队列，runLoop → runTurn 驱动"调模型 → 执行工具 → 再调模型"循环。
turn
循环的一圈：一次模型流式调用 + 由此产生的工具执行。一次用户 prompt 可能产生多个 turn。
transcript / AgentMessage
会话消息序列。AgentMessage 是能装 user/assistant/toolResult/自定义角色的联合容器；JSON 形状与上游逐字段一致。
Provider
ai/types.go 的接口：把标准化 transcript 变成某家模型的 wire 请求并产出统一事件流。换模型 = 换 Provider。
StreamFn
agent loop 实际调用的"发起一次模型流"的函数类型（agent/stream_fn.go）。Provider 会适配成 StreamFn。
steering / follow-up queue
Agent 的两条待投消息队列：steering = 运行中插进来的指令，follow-up = 排队等当前 run 结束的消息。
InteractiveMode
internal/codingagent 里交互模式的编排者：持有 Session ↔ Agent ↔ TUI ↔ 扩展宿主的全部连线，handleAgentEvent 是事件总线。
app mode
cmd/pig 的运行模式：interactive（默认 TUI）、print（--print 一次性输出）、rpc（--mode rpc 行 JSON 机器接口）。
SessionManager
internal/codingagent 里管会话文件的组件：创建、追加、resume、分页加载。持久化类型来自 durable/。
